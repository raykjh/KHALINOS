# KHALINOS

## Short description

KHALINOS is an evidence-gated autonomous production agent that turns one authorized goal into a bounded Browser or Godot prototype, executes the work asynchronously on Google Cloud, and marks it complete only after real runtime evidence and role-separated verification pass.

## The problem

Long-running coding agents often make the user the hidden workflow engine. The user must restate scope, watch every intermediate step, notice silent requirement drift, and decide whether a claimed result actually ran. KHALINOS replaces that supervision loop with an immutable outcome contract, least-authority Capability Packs, receipt-gated Quests, deterministic runtime checks, and a final digest-bound checkpoint.

## What KHALINOS does

1. The user supplies a goal and optional authoritative materials.
2. A bounded Route Advisor compares the goal only with approved ToolPack manifests.
3. SixSense asks only material unanswered questions and presents an explicit scope, evidence, budget, and duration preview.
4. After one authorization, a Cloud Run Job plans, produces, runs, and verifies the result without Codex or another development assistant in the execution path.
5. Firestore-backed live telemetry shows the selected profile, composed Capability Packs, current agent, Cloud execution ID, Gemini calls, verifier state, and M01–M06 receipt milestones.
6. A result becomes downloadable only after deterministic runtime checks and the role-separated Verifier pass. Otherwise KHALINOS stops safely rather than guessing completion.

The submitted Godot proof includes two compositions. Trinity uses top-down combat, profession progression, presentation, audio, profile-selected combat effects, gameplay probe, and sprite-atlas capabilities. The side-scroll destination profile reuses the same fixed agent ceiling but binds lane combat, destination progression, a different effect-role selection, and a different probe. This demonstrates pack composition, not arbitrary game-generation scope.

## Google technology

- Gemini 3.5 Flash on Vertex AI for schema-bound planning, production, and verification roles
- Google ADK 2.6.2 for each `LlmAgent`
- Nano Banana image generation through Vertex AI for bounded visual foundations
- Cloud Run service for the authenticated UI and immutable dispatch
- Cloud Run Job for asynchronous execution
- Firestore for owner-bound run state and live telemetry
- Cloud Storage for briefs, candidate evidence, receipts, manifests, renders, and verified source ZIPs
- Google OpenID Connect for owner-bound private projects and downloads

## Data sources

KHALINOS does not require a third-party business dataset. It processes the user's goal and optional user-provided text, image, or admitted source material. Hackathon Cloud proof runs use original synthetic briefs, Nano Banana visual foundations, and repository-contained generated combat-effect sheets. An optional development-only licensed-art path was tested against user-approved AetherAI assets; those originals remain outside the repository and Cloud image and are not redistributed as an asset pack. Private project records are separated by the verified Google subject identifier.

## Findings and learnings

- Model-written scope must remain subordinate to a host-controlled manifest binding. A stale or empty ToolPack binding is a safe-stop condition, not a reason to continue.
- Runtime evidence must exercise acceptance criteria; source inspection or a plausible screenshot is not enough.
- A role-separated verifier inside one product trust boundary is useful but is not an external audit organization. Deterministic probes and digest-bound evidence compensate for that limitation.
- Fixed agent slots can consume different least-authority Capability Pack combinations without inventing a new agent for each genre.
- Visual generation and mechanics verification are separate quality axes. The current Godot proofs demonstrate real mechanics and rendering but remain prototype-level visual products.

## Measured proof

On the latest immutable Cloud image, the side-scroll composition completed in 2 minutes 42.43 seconds with zero interventions after dispatch, 12 Gemini calls, three immutable receipts, 30/30 deterministic checks, and a final role-separated verifier PASS. Trinity passed 58/58 checks on the same digest with a different Agent–Capability composition. A separate authenticated Chrome qualification proved that the UI horse, active agent, Capability Packs, Gemini calls, verifier state, and M01–M06 cargo are derived from persisted Cloud state rather than a scripted animation.

## Product boundary

KHALINOS is not a general-purpose coding chatbot and does not claim arbitrary repository completion, production-scale reliability, external organizational verification, or commercial game polish. Once deployed it executes approved profiles without Codex; adding profiles, changing Capability Packs, fixing KHALINOS, and deploying releases remain normal product-development work.
